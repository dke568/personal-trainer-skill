# Резервная копия и восстановление

scripts/diary_backup.py создаёт текстовый JSON-снимок только разрешённых файлов
тренировочного состояния. Клинические файлы, код, токены и другие каталоги
в него не включать. Сначала читать свежий форк на точном SHA; source_commit
не является самостоятельным доказательством происхождения — проверить его GitHub.

1. Проверить цепочку изменений, хеши первичных файлов и производную сводку.
2. create --directory ... --repository owner/repo --source-commit SHA
   --created-at YYYY-MM-DD --out NEW_FILE.json. Существующий файл не перезаписывать.
3. Сохранить копию отдельно от форка и проверить доступность конкретной версии.
4. check --backup FILE; restore --backup FILE --destination NEW_DIRECTORY.
   Восстановление допускается только в новый каталог; действующий дневник не затирать.
5. Сравнить все байты восстановленных файлов и повторить validate/summary verify.

Снимок является копией состояния на указанный коммит, а не текущей версией навсегда.
Хеши выявляют порчу, но не аутентифицируют злоумышленника, способного переписать
весь конверт и историю. Для проверки происхождения сверять SHA с GitHub.
Проверка локального restore не доказывает, что отдельное хранилище сохранило файл.
В отчёте отдельно фиксировать сохранение, чтение этой версии и восстановление.
Не создавать периодическое расписание без запроса пользователя.
