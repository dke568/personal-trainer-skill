# Дневник
## Файлы
profile.json — цели, предпочтения, оборудование и ограничения.
events.jsonl — события с источником.
programme.md — действующий или пробный план.
decisions.md — решения и условия пересмотра.
handoff.md — точка входа для нового чата.

Временный файл не гарантирует память. Используй выбранное постоянное
хранилище и проверяй результат записи. Публичный репозиторий доступен всем:
отделяй приватный профиль от публичного кода.

## События
Обязательны schema_version, id, type, status, date, date_precision,
recorded_at и source. Тип: session, measurement, plan, note.
Статус:
- completed: подтверждено пользователем;
- recalled: приблизительное воспоминание;
- planned: будущее намерение;
- adjusted: изменённое предложение;
- in_progress: незавершённая работа;
- unknown: выполнение/содержание неясно.

Точная дата: date=YYYY-MM-DD и date_precision=day.
Без точной даты: date=null, date_precision=month/unknown; period=YYYY-MM
при необходимости. Для даты из неподтверждённой сводки допустимо
reported_unverified с объяснением. recorded_at — дата внесения записи.

source содержит kind и note. Для настоящих результатов: user_report,
user_summary, observed_material. synthetic_example исключается из аналитики.
Подход содержит kind=working/warmup, load_kg, reps; rir может быть null.
Указывай load_basis: barbell_total, plates_only, machine_stack_label,
bodyweight или other; для машины — equipment_id при наличии.
Неизвестные load_kg/reps допускаются как null; не подставляй число.
В плане вместо reps можно указать reps_min/reps_max. При записи выполнения
нужны фактические reps либо null с объяснением.

## Исправления
История дополняется. Исправление — полноценная новая запись того же типа
с новым id и supersedes=id прежней активной записи. Объясни причину.
Исходник остаётся; аналитика использует актуальную версию.
Учебные synthetic_example не могут заменять реальные события.

Выполнение плана — новый session, не смена статуса plan.
Можно указать fulfills_plan_id. Копируй только подтверждённые параметры.

## Аналитика
Недельный объём: только session/completed с точными датами и явно рабочими
подходами. Планы, воспоминания и недатированные сессии показывай отдельно.
При неполном покрытии это известный минимум, а не полный недельный объём.
Без RIR не утверждай одинаковую тяжесть подходов. Тоннаж не сравнивай
между разными упражнениями и машинами.

direct_muscles/indirect_muscles — прозрачная классификация для учёта,
не измеренная физиологическая доля эффекта.

## Новый чат
Handoff содержит дату актуальности, пути к состоянию, профиль, последние
факты, план, неопределённости и следующий шаг. Он не заменяет первичные
записи. Сначала читай состояние, затем советуй.
